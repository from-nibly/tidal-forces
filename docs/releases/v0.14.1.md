# Tidal Forces v0.14.1

## Wayland background responsiveness

Fixes a reproduced UI stall when Tidal Forces is hidden on a Hyprland workspace.
Blocking OpenGL vsync could wait for a frame callback the compositor withheld,
preventing the UI thread from handling events and triggering “not responding”
warnings. Bringing the window back could unblock it.

Linux Wayland now uses non-blocking buffer presentation. X11 retains vsync, and
existing repaint scheduling remains unchanged: no new polling thread or forced
renderer/backend switch. Backend detection follows winit's non-empty
`WAYLAND_DISPLAY` / `WAYLAND_SOCKET` signals rather than potentially stale session
labels. This does not change audio quality, authorization, playback or account data.

Verification: 199 normal tests, strict Clippy/fmt, release-mode check, X11 native
smoke and operator-authorized, account-free Wayland diagnostics. In the native
application A/B test, v0.14.0 could not finish its screenshot/close while hidden;
the patched application completed and exited while still hidden. Separate render
probes and stack traces identified `eglSwapBuffers` waiting in Mesa/Wayland.

The running user's player was not attached to, restarted or modified during these
tests. Signed-out tests used private XDG directories, isolated D-Bus and null audio.
The fix does not claim to solve every unrelated graphics-driver/compositor stall.

Upstream context: https://github.com/emilk/egui/issues/5136
