# Tidal Forces v0.13.0

## Favorite status after sign-in

- Checks saved tracks, albums and artists in the background, one page at a time, so heart controls can show known saved status without first browsing every library page.
- Membership stays in memory for the current account, with a 50,000-entry limit per category. Foreground loading and playback buffering take priority.
- Settings → **Library & Privacy** adds progress, **Stop checking** and **Refresh saved status**. Refresh after changes made in another app; these paginated reads are not atomic TIDAL revisions.

## Conservative handling of incomplete data

- Unavailable entries, missing totals and overlapping pages can still supply known saved items. They never establish that an unseen item is unsaved.
- Repeated IDs are deduplicated. A wholly repeated page ends that category's read rather than fetching repeated data indefinitely; other categories continue.
- Partial results explain which category could not be checked completely. Unknown hearts retain explicit actions menus.
- Account changes, local favorite writes and late replies cannot publish an obsolete in-progress check. A background membership update cannot turn a menu click already in progress into an unintended save/remove action.
- Manual library reads also avoid claiming complete membership across unavailable rows, duplicate IDs, unknown totals or changing counts.

## Verification

188 normal tests, strict Clippy and formatting, isolated single-instance and Secret Service contracts, release-mode checks, native smoke/layout fixtures and user review. The user confirmed partial-status reporting and filled hearts for known saved tracks. No live favorite mutations, credential migration/cleanup or agent-driven audible/device tests were performed.

Persistent caches, restored browse views and remaining P3 organization tools remain future work. No authentication clients, playback authorization or DRM controls changed.
