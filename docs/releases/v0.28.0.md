# v0.28.0 — PCM handoff and current-song buffering

First P4 audio-polish slice, approved after native playback review.

- Move decoder iteration and stream reads behind a bounded background PCM handoff.
  The output callback consumes complete frames without decoder/network/disk reads
  or PCM-buffer allocation. Stop and replacement cancel queued frames; blocked
  retired workers remain capped rather than accumulating without limit.
- Treat underflow as buffering, not progress or listening history. Pause still
  works while the stream is waiting for data.
- Buffer the current song's compressed audio in private, anonymous temporary files
  with a 256 MiB per-stream file cap. Reuse its decoder and downloaded data for
  seeks, retaining occurrence identity, queue revision, position and pause intent.
  Fully buffered seeks need no new authorization/network request; AAC preroll still
  takes time. Missing DASH segments get priority and larger songs remain windowed.
  Oversized direct streams can have unsupported out-of-window seeks; those fail
  visibly rather than reading incorrect bytes. Stop/account/track replacement
  releases the buffer; no persistent audio library or credential/URL files are added.
- Preserve finite decoded samples before existing volume and output conversion.
  Reject malformed frames, nonfinite samples and unexpected format changes.

Prepared-next playback and continuous inter-track handoff are still pending.
This release does not claim gapless playback, add DSP, implement output-device
recovery or advance P5 radio continuation.
