# v0.22.0 — Paged playlist reorder verification

- Extend immediate top/bottom/up/down moves to fully loaded owned playlists of 2–50,000 available tracks, in Original order without filtering/reverse, videos or unavailable rows. No second confirmation is added.
- Verify the frozen source and exact result one 100-row page at a time, yielding while playback buffers. Check account, ownership, revision, count and raw page boundaries; preserve duplicate occurrences.
- Recheck ownership/revision before one conditional write. Require a new write revision and complete matching read-back; never blindly retry or roll back an uncertain mutation.
- Allow cancellation before the move. Navigation, Refresh, account changes and close signal queued work to stop; interrupted post-write verification requires Refresh and inspection.
- Retain all loaded tracks and view options after verified success, clear selection and update the revision. The playback queue is unchanged. Eligibility checks avoid copying the full playlist during rendering.

Verified with 247 normal tests, strict Clippy/format/release checks, isolated instance/Secret Service contracts, and native 205-track responsive fixtures and smoke checks. Tests cover paged verification, duplicates, maximum bounds, cancellation around commit, stale/mismatched responses, buffering yield, backpressure, immediate menu actions and preserving the loaded view. No agent-run live account mutations or audible/device tests; synthetic contracts do not establish live mutation interoperability.
