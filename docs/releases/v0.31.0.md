# v0.31.0 — combined P4 audio bundle

Approved after the combined native review. Local verification passed 390 normal
tests on Rust 1.95 and 1.99, strict application Clippy, native UI/release smoke,
and isolated null-output and D-Bus contracts. Physical-device validation remains
separately gated as described below.

- Native Linux output picker for PulseAudio and PipeWire's Pulse server. Saved
  selections match device identity and port, not a stale handle. Desktop first use
  and older preferences require an explicit output choice before playback. Unidentified
  outputs require selection again after restart. Missing/changed outputs pause
  and require explicit retry; there is no automatic compatibility-device fallback.
- Optional ten-band EQ, preamp, stereo balance/mono and track/album normalization
  using TIDAL's documented SDK gain policy. Missing gain remains unavailable.
  DSP defaults off, preserves bypass samples, runs before the bounded PCM ring,
  reserves EQ headroom and limits peaks only on processed paths.
- Short, complete-frame start/resume/pause/volume ramps and smoothed DSP changes.
  Safety cancellation stays immediate. Native seek/load changes flush queued
  client audio before resuming.
- Continuous matching-FLAC handoffs remain supported with bypass or matching
  stateless processing. Stateful EQ, changing normalization, mixed formats and
  AAC without verified trim information use ordinary transitions, not crossfade.
- Confirmed unavailable tracks remain readable and subtly dimmed. Account-local
  markers are bounded and expire; five consecutive failures stop the queue.
  Authentication, subscription, transient, asset-readiness and decoder failures
  are not automatically skipped.
- Playback settings are scrollable with a compact selector in small/high-zoom
  windows. The player-bar quality label opens those settings and distinguishes
  source format, local processing and known output-engine details.

## Limits and validation gates

The native engine requests 48 kHz stereo float samples; this is not a DAC format
or bit-perfect claim. Port notifications cannot guarantee that already-buffered
sound never reaches another physical route. Explicit compatibility output has no
physical-route protection. Hardware unplug/audible tests require separate opt-in.

Synthetic/native UI checks and private null-server tests do not establish real
headphone behavior. P5 radio/autoplay, Cast, Connect and track crossfade are outside
this release. See `docs/audio-processing.md` and `docs/output-validation.md`.

Linux builds now require the system libpulse client library. The vendored Rust
binding has a narrow callback-cancellation fix with private-server regression tests;
see `vendor/README.md`. No daemon or helper executable is bundled.
