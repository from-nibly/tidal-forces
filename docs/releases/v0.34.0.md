# v0.34.0 — Native Google Cast

Operator approved publication and managed installation after native preview review.

## Features

- Cast controls on the main, branded mini and classic players. The live device
  picker lists receiver names/models and This computer; no manual address or
  certificate-policy UI. Discovery streams add/update/remove events while open,
  deduplicates Cast IDs, preserves advertised endpoints, and stops when closed.
- Honest selected/connecting/connected/stopping/unconfirmed states. Returning to
  local output requires owned release and stays paused at the current position.
- One occurrence-aware shared queue, including manual priority, duplicate tracks,
  shuffle and repeat. Shared transport/media-key/CLI controls target the active
  output. Queue continuation requires explicit owned natural completion; errors,
  cancellation, disappearance and elapsed time never count as completion.
- Track title, artist, album and public HTTPS artwork metadata accompany each LOAD.
  No local media server, relay, transcoding or receiver account-token handoff.
- Acknowledged local-output release before remote LOAD, account/generation fences,
  scoped commands/events and no automatic reconnect/local fallback/quality downgrade.
- Reviewed legacy Cast certificate-chain interoperability is built in, while trusted
  roots, key/path/validity constraints, signed revocation and fresh SHA256 nonce/TLS
  binding remain enforced. This retains the documented weaker certificate-signature
  tradeoff, not an equivalent-strength modern certificate chain.

## Verification

- 564 normal application tests and72 Cast example tests pass on Rust1.95 and1.99.1;
  strict all-target Clippy and formatting pass. Opt-in live/account tests excluded.
- Exact isolated authentication/TLS and native null-Pulse/PipeWire handoff contracts
  pass; no real local-output test is implied by null-server results.
- Approved receiver tests verified FLAC, AAC-LC and HE-AAC at44.1kHz, pause/resume,
  forward/backward paused seeks and playing seeks on excerpts/full track timelines,
  with owned cleanup. A finite excerpt separately passed explicit natural completion.
- Corrected native discovery found five devices after an independently approved,
  interface-only host mDNS firewall allowance. The application does not install or
  alter firewall rules or network daemons.
- Private UI tests cover picker interaction, connection states, viewport ownership,
  minimum mini/classic layouts, metadata, queue/repeat/shuffle and control races.

## Limits and known issues

- Reviewed clear DASH only; up to fifteen minutes per track. Direct/BTS sources,
  additional codecs/sample rates, groups, IPv6, expiry recovery and every discovered
  receiver model are not established by the current receiver evidence.
- Receiver output format/bit-perfect output is not reported. Local DSP and visualizer
  processing do not apply to Cast. Genuine TIDAL Connect is not included.
- Actual receiver artwork rendering and continuous multi-track playback on the final
  cohesive build have not had a new live validation pass. Private queue/metadata
  contracts and earlier receiver transport tests are separate evidence, not a claim
  of those unperformed tests. The full-length song's corrected terminal collector
  was verified on a finite natural-end excerpt, not another full-song rerun.
- Some track starts intermittently pause with "decoded audio does not match manifest."
  The operator requested investigation after this release; decoder/manifest safety
  validation has not been relaxed or bypassed.

Version approval does not authorize real account mutations, credential migration,
additional audible/device tests or replacing the approved review preview during
managed installation.
