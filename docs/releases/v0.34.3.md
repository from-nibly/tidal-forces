# v0.34.3 — Bounded skipping for playback-readiness error 4005

The operator reviewed the native preview and explicitly approved commit,
publication and managed installation.

- Treat only playback-authorization HTTP401/substatus4005 as a typed not-ready
  failure. Advance to the next shared-queue occurrence instead of stopping on it.
- Retain code4005 in the skip notice; stop after five consecutive missing/not-ready
  failures rather than traversing an inaccessible queue indefinitely.
- Preserve duplicate occurrences, manual Up next priority, shuffle and repeat
  behavior, account/generation guards, paused playback and output-fault protection.
- Apply the same policy to Cast preparation only after acknowledged output release,
  before LOAD. Active receivers and unknown release remain protected. Successful
  playback or explicit retry resets the streak; authorization alone does not.
- Keep other authorization/subscription, network and decoder failures out of the
  skip path. No credential renewal because of4005, same-asset retry, quality fallback,
  media relay or permission bypass is introduced.
- Describe temporary account-scoped row markers as unavailable/not-ready, not proof
  that a track was removed from TIDAL's catalog.

580 application tests and72 Cast example tests pass locally on Rust1.95, with strict
all-target Clippy, formatting and optimized isolated native/null-audio smoke checks.
Offline regressions cover typed routing, bounded failures, stale replies, queue modes,
paused/faulted output and Cast handoff safety. The operator confirmed ordinary
Cadillac playback after a preview-launch TMPDIR lifetime error was corrected.

A separately authorized, single playback-authorization check for the originally
reported Mest track returned HTTP200, not4005. This does not prove audio playback or
live skip behavior; no media download/audio test or broader catalog scan was performed.
The unrelated decoder/manifest mismatch investigation remains paused.
