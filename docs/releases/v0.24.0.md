# v0.24.0 — Distinct saved-playlist unfollowing

- Offer **Playlist… → Unfollow playlist…** for known saved, non-owned playlists. Unknown membership or ownership never enables the action. Unfollowing is distinct from deleting your own playlist and requires explicit confirmation.
- Freeze account, ID and metadata revision; recheck ownership/revision before one v2 removal request containing only the playlist TRN, never a folder TRN or the owned-playlist DELETE endpoint.
- Check removal using one bounded playlist/favorite listing response. Only complete, unique listings of at most 50 entries establish absence. Large, partial, overlapping, malformed or failed reads remain explicitly unverified—not false membership.
- Preserve the current playlist view, queue and local pins. Navigation/account/close cancel queued work; uncertain results require Refresh and inspection, never automatic retry.

Verified with 272 normal tests, strict Clippy/format/release checks, isolated instance/Secret Service contracts, native responsive fixtures and signed-out smoke checks. Tests cover ownership/account/revision guards, the exact playlist-TRN route, cancellation, complete versus unknown membership, typed action/result isolation and actual button clicks that never dispatch deletion. No agent-run live account mutations or audible/device tests; synthetic contracts do not prove live v2 removal/listing interoperability. No membership revision guard is assumed.
